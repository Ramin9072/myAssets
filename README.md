# مدیریت دارایی‌های من

اپلیکیشن وب فارسی (RTL) برای ثبت تعداد سکه، دلار و طلای گرمی و محاسبه ارزش کل به **ریال** با قیمت روز بازار ایران.
Frontend: React + TypeScript (Vite) · Backend: Node.js + Express (TypeScript) · ذخیره‌سازی: فایل JSON سمت سرور.

## نصب و اجرا (ویندوز / مک / لینوکس)

پیش‌نیاز: Node.js نسخه ۲۰ یا بالاتر.

```bash
npm install
copy .env.example .env      # در مک/لینوکس: cp .env.example .env   (اختیاری؛ بدون آن هم اجرا می‌شود)
npm run build
npm start
```

سپس `http://127.0.0.1:8787` را باز کنید. (به‌صورت پیش‌فرض فقط روی همین رایانه در دسترس است.)

حالت توسعه (با بارگذاری خودکار): `npm run dev` ← رابط کاربری روی `http://localhost:5173`.

دستورات دیگر: `npm test` (تست‌ها) · `npm run typecheck` · `npm run check:provider` (دریافت زنده از سرویس قیمت و چاپ نتیجه تفسیرشده؛ **قبل از اولین استفاده حتماً اجرا کنید**).

## انتشار روی Vercel

1. پروژه را روی یک مخزن **خصوصی** GitHub بگذارید (`api/index.js` باید در مخزن باشد؛ `data/` و `.env` ignore شده‌اند).
2. در Vercel: **Add New → Project** و مخزن را Import کنید (Framework: Vite؛ تنظیمات از `vercel.json` خوانده می‌شود).
3. در همان پروژه: **Storage / Marketplace → Upstash Redis** را اضافه و به پروژه وصل کنید. متغیرهای `KV_REST_API_URL` و `KV_REST_API_TOKEN` خودکار ساخته می‌شوند.
4. در **Settings → Environment Variables** متغیر `APP_PASSWORD` را با یک رمز قوی بسازید (اختیاری: `SESSION_SECRET` با یک رشته تصادفی بلند).
5. **Deploy** بزنید (یا بعد از افزودن متغیرها Redeploy). آدرس را باز کنید، با رمز وارد شوید.

نکات:
- در Vercel ذخیره‌سازی روی Redis است (کلیدهای `my-assets:*`)، نه فایل. پشتیبان‌گیری/بازیابی از صفحه «دارایی‌ها» همان‌طور کار می‌کند.
- تاریخچه در Redis به **۲۰۰ محاسبه آخر** محدود است (محدودیت اندازه هر مقدار).
- بعد از هر تغییر در کد سرور، قبل از commit دستور `npm run build:api` را اجرا کنید تا `api/index.js` به‌روز شود.
- بدون `APP_PASSWORD` در Vercel، همه درخواست‌ها با پیام خطای پیکربندی رد می‌شوند (عمداً، تا داده‌ها عمومی نشوند).
- قفل هم‌زمانی فقط داخل هر اجرای سرور است؛ برای استفاده تک‌کاربره کافی است.
- حدس‌زدن رمز با تأخیر ۰٫۷ ثانیه کند می‌شود، اما محدودیت تعداد تلاش سراسری ندارد؛ رمز قوی بگذارید.
- اجرای محلی (`npm start`) همچنان بدون رمز و با فایل کار می‌کند؛ اگر `APP_PASSWORD` را در `.env` بگذارید، صفحه ورود فعال می‌شود.

## نصب روی موبایل

**روش ساده (بدون APK): نصب به‌صورت PWA.** بعد از انتشار روی Vercel، آدرس را در Chrome گوشی باز کنید ← منوی ⋮ ← «Add to Home screen / Install app». برنامه با آیکن و تمام‌صفحه اجرا می‌شود.

**روش APK:** پروژه شامل `capacitor.config.ts` و workflow ‌ی `.github/workflows/build-apk.yml` است که در GitHub یک APK دیباگ می‌سازد (که همان آدرس Vercel شما را داخل برنامه باز می‌کند؛ بدون اینترنت کار نمی‌کند):
1. در مخزن GitHub: Settings → Secrets and variables → Actions → **Variables** → متغیر `APP_URL` را با آدرس https برنامه روی Vercel بسازید.
2. تب **Actions** ← «Build Android APK» ← **Run workflow**.
3. بعد از پایان، از بخش Artifacts فایل `my-assets-apk` را دانلود، از zip درآورید و `app-debug.apk` را روی گوشی نصب کنید (اجازه «نصب از منابع ناشناس» لازم است).

## ساختار پوشه‌ها

```
shared/      تعریف دارایی‌ها، اعتبارسنجی و پردازش اعداد (مشترک بین فرانت و بک‌اند)
server/
  domain/    محاسبات مالی (Decimal)، تبدیل واحد، ساخت قیمت‌ها، بررسی سازگاری
  providers/ لایه مستقل دریافت قیمت (nerkhsanj.ts + قرارداد types.ts + registry در index.ts)
  services/  priceService (دریافت/کش/تلاش مجدد) و calculationService
  storage/   نوشتن اتمیک فایل، assets/history/settings
  app.ts     API (REST)       index.ts  راه‌اندازی
src/         رابط کاربری React
tests/       تست‌های vitest
data/        assets.json اولیه + فایل‌های runtime (history.json, settings.json, last-prices.json, backups/)
examples/    assets.sample.json (نمونه با اعداد فرضی)
```

## وب‌سرویس قیمت: نرخ‌سنج (Nerkhsanj)

- آدرس: `GET https://nerkh.jahankhahan.shop/data/live.json` — **رایگان، بدون کلید و ثبت‌نام**، به‌روزرسانی هر دقیقه.
- واحد: **تومان**؛ بازار: **آزاد تهران**. زمان قیمت: فیلدهای `date` (شمسی) و `time` (به وقت تهران) در پاسخ.
- فیلدهای استفاده‌شده در `rates`: `dollar`، `gold` (۱۸ عیار)، `gold24`، `bahar`، `half`، `quarter`.
- سرور برنامه قیمت‌ها را می‌گیرد (نه مرورگر)، پس CORS مسئله نیست. طبق شرایط استفاده سرویس: حداکثر دقیقه‌ای یک‌بار (برنامه به‌طور خودکار رعایت می‌کند) و ذکر منبع (در رابط کاربری نمایش داده می‌شود).
- کلید API لازم نیست. اگر در آینده به سرویس کلیددار رفتید، کلید را فقط در `.env` (متغیر `PRICE_PROVIDER_API_KEY`) بگذارید؛ هیچ کلیدی در فرانت‌اند یا کد قرار نمی‌گیرد.
- قبل از محاسبه: واحد، مثبت‌بودن، ساختار و زمان پاسخ بررسی می‌شود، و نسبت قیمت سکه به طلا سنجیده می‌شود تا خطای ده‌برابری ریال/تومان رد شود.

### تغییر ارائه‌دهنده در آینده

1. فایل جدید در `server/providers/` بسازید که رابط `PriceProvider` (در `types.ts`) را پیاده کند: واحد خام (`toman`/`rial`)، بازار دلار، و کلیدهایی که ندارد.
2. در `server/providers/index.ts` به آرایه `createProviders` اضافه کنید.
3. در صفحه «تنظیمات ← منبع قیمت» انتخابش کنید. هیچ‌یک از منطق محاسبات تغییر نمی‌کند.

## محل ذخیره اطلاعات و پشتیبان

- دارایی‌ها: `data/assets.json` (متن ساده؛ با هر ویرایشگر قابل ویرایش — کلیدهای ناشناخته یا مقدار منفی هنگام بارگذاری خطا می‌دهند و فایل بازنویسی نمی‌شود).
- تاریخچه: `data/history.json` · تنظیمات: `data/settings.json` · آخرین قیمت معتبر: `data/last-prices.json`.
- نوشتن اتمیک است (فایل موقت ← fsync ← rename)؛ اگر فایل بعد از بارگذاری بیرون از برنامه تغییر کند، ذخیره با خطای تعارض رد می‌شود.
- پشتیبان: صفحه «دارایی‌ها ← دانلود نسخه پشتیبان». بازیابی با تأیید انجام می‌شود و نسخه قبلی خودکار در `data/backups/` می‌ماند.
- برای پشتیبان‌گیری کامل می‌توانید کل پوشه `data/` را کپی کنید.

## محدودیت‌های شناخته‌شده

- **سکه‌های «قبل از ۱۳۸۶»:** نرخ‌سنج قیمت مستقل برای آن‌ها ندارد؛ این سه قلم همیشه «قیمت نامشخص» می‌شوند (اگر مقدار > ۰ باشد، جمع کل «ناقص» علامت می‌خورد). قیمت سکه معمولی جایگزین آن‌ها نمی‌شود. برای این موارد در «تنظیمات ← قیمت دستی سکه‌ها» قیمت را خودتان ثبت کنید؛ قیمت دستی فقط جای خالی قیمت سرویس را پر می‌کند، خودکار به‌روز نمی‌شود و با برچسب «دستی» و زمان ثبت در جدول و تاریخچه می‌آید. قیمت دستیِ بیش از ۲ برابر یا کمتر از نصف قیمت سکه هم‌نوع در سرویس (نشانه اشتباه واحد) رد می‌شود.
- **نگاشت `bahar`:** مستندات سرویس طرح (قدیم/جدید) این کلید را مشخص نمی‌کند. این برنامه آن را «سکه تمام بهار آزادی» در نظر می‌گیرد (`NERKHSANJ_KEY_MAP` در `server/providers/nerkhsanj.ts`). با مقایسه با بازار، درستی آن را خودتان تأیید کنید.
- **قیمت‌ها یک عدد هستند:** تفاوت خرید/فروش و قیمت تئوریک (ارزش ذاتی) در داده سرویس تفکیک نشده؛ نتیجه «ارزش تقریبی بازار» است، نه قیمت قطعی فروش.
- **عیار غیر ۱۸/۲۴:** قیمت از ۱۸ عیار محاسبه می‌شود (بدون اجرت/سود) و در جدول «محاسبه‌شده» علامت می‌خورد. قیمت ۲۴ عیار فقط اگر سرویس `gold24` بدهد مستقیم است.
- **دلار رسمی:** این سرویس فقط بازار آزاد دارد؛ انتخاب «نرخ رسمی» خطای صریح می‌دهد و ترکیب نمی‌شود.
- **خارج از ساعت بازار:** سرویس `time` را خالی می‌گذارد؛ زمان دقیق نامعلوم است و محافظه‌کارانه ابتدای همان روز فرض می‌شود، پس معمولاً پیام «قیمت قدیمی» می‌آید و محاسبه فقط با تأیید شما انجام می‌شود.
- مقدار صفر برای یک دارایی بدون قیمت، جمع را ناقص نمی‌کند؛ تاریخچه محدودیت اندازه ندارد.
- برنامه تک‌کاربره است. اجرای محلی بدون `APP_PASSWORD` احراز هویت ندارد؛ بدون رمز روی اینترنت منتشرش نکنید.

## چک‌لیست وضعیت

**پیاده‌سازی و با تست خودکار بررسی‌شده (۵۷ تست):** پردازش ارقام فارسی/اعشار · تبدیل تومان↔ریال و عدم تبدیل دوباره · محاسبه هر نوع دارایی و جمع (با Decimal) · مقدار اعشاری · قیمت ناموجود · API ازدسترس‌خارج، کند (timeout)، پاسخ نامعتبر · قیمت قدیمی و تأیید صریح · بررسی ده‌برابری · ذخیره/بارگذاری، تعارض ویرایش، فایل خراب · پشتیبان و بازیابی · تاریخچه پایدار و بدون بازنویسی · جلوگیری از درخواست هم‌زمان · هدر امنیتی نوشتن · رمز عبور (ورود، خروج، انقضا، حالت بدون پیکربندی) · ذخیره‌سازی Redis (با Redis شبیه‌سازی‌شده) و سقف تاریخچه.
تایپ‌چک (`tsc`) و build تولید موفق؛ اجرای سرور و پاسخ API دستی بررسی شد.

**نیازمند بررسی/دسترسی شما:**
- استقرار واقعی روی Vercel و Upstash انجام نشد. فقط بسته‌ی `api/index.js` محلی با یک Redis شبیه‌سازی‌شده اجرا و آزمایش شد (ورود، خواندن دارایی‌ها، ذخیره در Redis). اینکه Vercel مسیر `/api/*` را دقیقاً مطابق `vercel.json` به تابع می‌رساند و اینکه سرورهای Vercel به نرخ‌سنج دسترسی دارند، تأیید نشده است.
- اتصال زنده به نرخ‌سنج: محیطی که این پروژه در آن ساخته شد به آن دامنه دسترسی نداشت، و ساختار پاسخ فقط از مستندات رسمی سرویس گرفته شد، نه یک فراخوانی واقعی. با `npm run check:provider` تأیید کنید؛ اگر نام فیلدها فرق داشت فقط `nerkhsanj.ts` را اصلاح کنید.
- ظاهر رابط کاربری در مرورگر واقعی (موبایل/دسکتاپ) با چشم بررسی نشده؛ فقط build و تایپ‌چک شده است.
- ویندوز: منطق تلاش مجدد برای قفل‌شدن فایل در rename نوشته شده ولی روی ویندوز اجرا نشده است.
